# PPO：限制每步策略改变的强化学习算法

## 直觉

PPO（Proximal Policy Optimization）是策略梯度算法，核心问题是：当前批数据看起来有利时，怎样多做几步梯度更新而不让新策略突然失控？它通过概率比的裁剪，减少把某一动作概率推得过远的激励。在 RLHF 中，PPO 常把奖励模型分数加上 KL 惩罚作为回报；PPO 本身并不规定奖励来自人类。

## 前置知识与简化公式

用旧策略 `πold` 采样 `(s_t,a_t)`，优势估计为 `A_t`，新旧动作概率比为 `r_t=πθ(a_t|s_t)/πold(a_t|s_t)`。PPO-Clip 的简化目标是：

```
Lclip = E[min(r_t*A_t, clip(r_t, 1-ε, 1+ε)*A_t)]
```

`ε` 常取小值。正优势下，超过上界的继续增益会被截断；负优势下，过度降低概率也不再获得目标收益。这不是硬性保证参数或行为绝不变化，而是一个近端更新的近似手段。

## 流程

1. 冻结旧策略，从它采样一批完整回答或轨迹。
2. 由 RM、验证器或环境给回报，拟合价值函数并计算优势。
3. 在同一批数据上做若干 mini-batch 更新，监控近似 KL，必要时早停。
4. 将新策略变为下一轮旧策略，再重新采样。

这解释了为何 PPO 是 on-policy：过度复用很旧数据时，`r_t` 与优势不再对应当前交互分布。其“可多 epoch 用一批”不等于任意离线回放。

## 小例子

数学回答经验证得 1 分，错误得 0 分。若某段推理使正确答案出现，`A_t>0`，PPO 提高该轨迹 token 概率；若一次更新把比率推到 `1+ε` 之外，裁剪目标不再鼓励继续推。实际 RLHF 还会把与 `πref` 的 KL 作为额外回报或惩罚项。

## 常见误区

PPO 不是“加 KL 就是 PPO”：PPO-Clip 可不在目标中直接写 KL，工程上却常监控或另加参考 KL。它也不要求奖励模型，机器人环境和可验证奖励同样可用。裁剪不能自动消除奖励黑客、价值估计误差或数据偏差。
