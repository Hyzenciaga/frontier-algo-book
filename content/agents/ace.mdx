# ACE：把上下文当作会演化的工作手册

这里的 ACE 指 Zhang 等人的 **Agentic Context Engineering: Evolving Contexts for Self-Improving Language Models**，不是泛指所有 prompt engineering。论文的核心选择是：不微调模型权重，而把策略、经验和证据维护成可演化的上下文“playbook”。每次执行得到的自然反馈，经过生成、反思、整理三个角色转成增量条目；下一次任务再把这本手册提供给同一个基础模型。

## 前置知识

上下文是一次调用输入的 token，例如系统指令、工具说明、检索文档和记忆；权重是训练后持久的参数。长上下文并不天然可靠：反复把经验压缩成一段摘要，会因篇幅偏好丢掉罕见却关键的细节，论文称这类退化为 brevity bias 与 context collapse。要理解 ACE，还需知道离线适应可以更新系统提示词，在线适应可以更新代理记忆。

## 机制

**Generator** 读取现有 playbook，为新问题生成推理或执行轨迹；**Reflector** 分析轨迹与结果，从成功和错误中提炼经验；**Curator** 将经验整理为增量条目，再由确定性逻辑合入上下文，而非整段重写。论文条目包含唯一标识、有用／有害计数和策略内容，并通过更新与去重控制冗余。教学实践中还可补充“何时适用、证据是什么”，便于追溯。部署时，代理读取当前 playbook 来规划和调用工具。整个环路更新的是外部文本／记忆；除非另行训练，基础模型参数不变。

## 例子

财务问答代理多次遇到“金额字段有单位差异”。一次执行失败后，反思器记录“先确认币种与最小单位，再聚合”；整理器把它放入数据校验章节。以后同模型在相似表格上先执行这条检查。若新证据表明某接口固定以分为单位，策展器应添加适用范围，而非粗暴删除旧规则。

## 边界与误区

ACE 的“self-improving”是**上下文适应**，不能写成模型在持续训练。论文报告的是其设定、基准、模型与评测下的结果，不能外推为任何记忆系统都会提升。自然执行反馈也可能错误或被奖励投机；条目会过时、互相冲突或泄露敏感信息，因此需要来源、版本、访问控制和回滚。把更长的 prompt 等同于 context engineering 同样不对：检索、结构、更新规则和验收共同决定效果。

## 自测

1. ACE 为什么避免每轮都把整份经验总结重写？
2. playbook 增加一条规则后，哪些状态改变了，哪些没有改变？
3. 为一条“工具调用失败”的经验设计适用条件与可验证证据。
