# RLHF：把人的比较转成优化信号

## 直觉

RLHF（Reinforcement Learning from Human Feedback）是一套训练框架：先让人比较候选回答，再将这种偏好转成可优化信号，最后用强化学习更新策略。经典实现常是 `SFT → 奖励模型（RM）→ PPO`，但这是一条常见管线，不是 RLHF 的定义本身；也可以用 DPO 等直接偏好目标替代显式 RM 加 PPO 的后两步。

## 前置知识

给提示 `x` 采样两个回答 `yw, yl`，标注者选择较好者。Bradley–Terry 假设奖励模型 `rφ` 满足：

```
P(yw ≻ yl | x) = sigmoid(rφ(x,yw) - rφ(x,yl))
L_RM = -log P(yw ≻ yl | x)
```

随后策略可最大化简化目标：

```
E[rφ(x,y)] - β * KL(πθ(.|x) || πref(.|x))
```

其中 `πref` 通常冻结为 SFT 策略。KL 防止模型只钻 RM 的空子；但它只是约束，不能证明奖励模型没有漏洞。

## 流程

先定义标注规范和冲突处理，再从当前模型或多个模型生成候选，收集排序并训练、保留测试 RM。用 PPO 等算法按 RM 回报更新策略，持续监测 KL、奖励、人工盲评与拒答率。实际系统还会混入预训练或 SFT 损失以减轻能力遗忘。

## 小例子

“解释合同条款”有 A（清楚且提醒咨询专业人士）和 B（自信地下结论）。标注者偏好 A，RM 学到相对分数；RL 阶段增加 A 类输出概率。若训练集中只奖励“看起来详细”，策略可能制造无用免责声明或冗长文本，这正是要用独立人工评审发现的 reward hacking。

## 常见误区

RLHF 不等于“模型听从每个标注员”。它拟合的是数据、规则和聚合流程产生的偏好。奖励模型也不是客观真理，面对分布外提示会错。更关键的是，DPO 可以使用同样的 `(x,yw,yl)` 人类偏好数据，却省去单独训练显式 RM；因此不能因未见 PPO 就断言不是偏好对齐。
