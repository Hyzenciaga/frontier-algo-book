# EAGLE：预测目标模型的特征，再长出草稿树

## 直觉

用户所说的 “ego” **推测**是 EAGLE（Extrapolation Algorithm for Greater Language-model Efficiency）；现有公开资料无法仅凭读音把这个指代当作确定事实。EAGLE 的特别之处不在于另训一个完整小语言模型逐词猜，而在于预测目标模型倒数第二层的上下文特征，再从特征产生候选 token。作者认为特征层的自回归比 token 层更容易，但特征预测本身有不确定性，必须显式处理。

## 前置

EAGLE 是投机采样框架的一类草稿器：目标模型仍计算验证概率，随机采样仍须按 `min(1,p/q)` 接受、首次拒绝后从 `[p-q]_+` 归一化残差采样。EAGLE 的「与普通解码分布一致」主张指这种正确验证设置，不意味着任意实现、量化设置或 greedy 演示都会逐字相同。

## 机制

原始 EAGLE 预测倒数第二层特征，并把「提前一个时间步的 token 序列」送入草稿过程以消除特征自回归的歧义；之后由轻量头产生 token 候选。工程上常扩成草稿树：多个可能 token 分支可在一次目标前向中并行验证，接受落在树上的最长有效路径。EAGLE-2 用草稿模型的置信度近似接受率，动态调整树形；EAGLE-3 在训练时模拟测试过程，并融合低、中、高层语义特征，改变的是草稿质量与树的构建方式，不是放弃目标验证。

## 例子

对于上下文「巴黎是法国的」，草稿树可能在第一层给出「首都」「城市」等分支，并继续扩展。目标模型并行看这些路径；若「首都」及其后续 token 依次通过，则整段前缀被提交。若某位置拒绝，则从该位置的目标/草稿残差分布取修正 token，而不是把树上另一个候选当作当然正确答案。

## 误区

EAGLE 不是「无需草稿模型」：它训练的是与目标内部特征耦合的轻量预测器。它也不是把 hidden state 直接当 token 输出。论文中不同 EAGLE 版本、模型、树参数和硬件下的加速数据不可横比；文档应注明版本（EAGLE、EAGLE-2 或 EAGLE-3）。若用户实际想问的是另一个拼作 ego 的项目，需要给出链接后再改名，不能据此条目反推。
