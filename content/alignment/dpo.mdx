# DPO：直接用偏好对拉开策略概率

import {DpoLab} from '@site/src/components/AlgorithmLab';

## 直觉

DPO（Direct Preference Optimization）从同一类偏好对出发，却不先单独拟合一个可部署的显式奖励模型、再运行 RL。它利用带 KL 正则的 RLHF 目标的解析关系，把隐式奖励写成策略与参考策略的对数概率比，再直接做二分类式损失。因此 DPO 省掉的是“单独训练 RM”和在线 PPO 采样，不是参考模型。

## 前置知识与简化公式

数据是 `(x, yw, yl)`：`yw` 被偏好，`yl` 被拒绝。固定 `πref` 后，常见 DPO 损失写作：

```
L_DPO = -log sigmoid(β * [
 log πθ(yw|x)-log πref(yw|x)
 -log πθ(yl|x)+log πref(yl|x)
])
```

这里序列 log 概率是各 token 条件 log 概率之和，`β` 控制相对参考分布的偏离尺度。式子为教学简化，长度处理、mask、batch 平均等依实现而定。`πref` 往往是冻结 SFT 模型，不能把它误删；它正是原始推导中 KL 正则的锚点。

## 流程

准备经过质量控制的偏好对；冻结参考模型；同时算当前模型与参考模型对胜、负回答的 log 概率；用上述损失更新当前策略。典型 DPO 是离线训练，可避免每轮生成、奖励打分和价值网络，但偏好对仍须覆盖真正会遇到的提示与候选分布。

## 小例子

同一提示下，`yw` 准确且简洁，`yl` 编造引用。若当前模型相对 `πref` 已更常给 `yw`、更少给 `yl`，损失变小；反之梯度会扩大这两个相对变化。它不是强迫 `yw` 的绝对概率无限变大，而是学习人类在成对选择中表达的方向。

## 常见误区

“DPO 没有 reward model”应准确理解为不必训练独立的显式 RM；理论中有隐式奖励重参数化。更错误的是“DPO 没有 reference”：标准 DPO 明确使用固定 `πref`。DPO 也不自动优于 PPO；在线探索、非静态目标、数据质量和算力会改变取舍。
