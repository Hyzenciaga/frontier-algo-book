# Agentic RL：在部分可观测的工具环境中分配长期回报

对一段聊天回复打分，常可把问题近似为“给定 prompt 生成一次答案”。代理型强化学习面对的对象不同：代理读页面、调用工具、等待结果、写入状态、再根据新观察行动；早一步的调用会改变后续看见的信息与可行动作。Agentic RL 因而以长时程、带工具的决策为中心。它不是某一种唯一算法，而是一种把语言模型纳入环境交互闭环的任务设定。

## 前置知识

部分可观测马尔可夫决策过程可写作 $\mathcal M=(\mathcal S,\mathcal A,\mathcal O,P,R,\gamma)$。真实状态 $s_t$ 不完全可见，代理只得到观察 $o_t$，以历史 $h_t=(o_0,a_0,\ldots,o_t)$ 或其记忆摘要近似信念状态。语言代理的动作有两类：文本 token 与结构化工具动作；环境则返回工具输出、异常、网页变化或任务验证。目标是提高

$$
J(\pi)=\mathbb E_\pi[\sum_{t=0}^{T}\gamma^t r_t]
$$

这里的“环境”必须可复位、定义终止并能评分，否则无法分辨模型学习、缓存命中和外部世界偶然变化。

## 机制

一次 rollout 交替执行观察、策略决策、工具执行和新观察，保存完整轨迹，包括 token 边界、动作 JSON、工具参数、返回值、时间和最终 verifier。训练器从终局成功、单元测试、成本、延迟、无效动作与安全约束组成奖励。折扣回报 $G_t=\sum_{k\ge t}\gamma^{k-t}r_k$ 为每一步提供归因；通常还减去价值基线 $V(h_t)$ 得 advantage $A_t=G_t-V(h_t)$，再以 PPO 等受约束策略梯度更新。KL 约束或 clipping 的作用是限制新策略偏离参考策略，避免一次偶然高分使语言行为坍缩。

最容易被忽略的是**动作空间与 mask**。若工具调用由特殊 action tokens 或 JSON 段表示，工具执行的奖励应归因于这些输出 token，而不是把整个模型回答的所有 token 都当作“调用动作”。token-level action mask 标记哪些位置可接收工具相关优势；文本推理 token 仍可从终局奖励得到学习信号，但要明确所用 credit assignment。还要验证掩码跨多 token 函数名、参数、关闭括号和失败重试是否对齐。没有这个边界，训练可能奖励模型写出工具结果的文字，而没有提升它发出可执行调用的概率。

奖励设计也必须分层。终局 verifier（订单确实创建、测试确实通过）最接近任务目标，却往往稀疏；过程奖励如无效调用惩罚、预算成本、格式合法性可降低探索难度，却可能让代理迎合代理指标。一个稳健做法是把硬约束设为环境拒绝或明确惩罚，把过程信号保持小于终局信号，并用只看终局成功的保留评测复核。对长轨迹，错误 credit assignment、高方差和工具非确定性会使简单“每一步平分奖励”特别不可靠。

记忆可把历史压缩后再输入策略，因而改变决策；它本身不是参数更新。参数学习发生在将 rollout、优势和 mask 交给优化器反向传播时。真实工具还有权限、不可逆副作用和分布漂移，训练沙箱的探索策略不能直接迁移到生产系统。

## 例子

以下示例计算一条含两次工具尝试的折扣回报，并明确哪些动作属于工具头的训练位置；可运行文件见 [完整 Python 示例](../../examples/agents/agentic-rl.py)。

```python
"""Credit assignment over a tool trajectory; no ML libraries required."""
rewards = [0.0, -0.1, -0.1, 1.0]  # read, invalid tool, valid tool, verified task
actions = ["read", "tool[bad]", "tool[good]", "answer"]
gamma = 0.9
returns, future = [], 0.0
for reward in reversed(rewards):
    future = reward + gamma * future
    returns.append(round(future, 3))
returns.reverse()
tool_mask = [False, True, True, False]
for action, value, is_tool in zip(actions, returns, tool_mask):
    print(f"{action:10} return={value:>5} train_tool_head={is_tool}")
```

实测输出：

```text
read       return=0.558 train_tool_head=False
tool[bad]  return= 0.62 train_tool_head=True
tool[good] return=  0.8 train_tool_head=True
answer     return=  1.0 train_tool_head=False
```

它展示的是数值归因，不是可训练的 Agentic RL 系统：没有 POMDP 环境、策略网络、价值函数、采样、token mask 构造或优化器。真实实现还应把工具执行放在隔离环境，并保存可复现种子和环境版本；否则同一策略的分数不可比较。

## 深入：轨迹与评测的最小契约

一条可用于复训的代理轨迹至少要关联任务实例、初始观察、每个模型输出、解析后的结构化 action、实际送入工具的参数、工具原始输出、环境版本、终止原因和 verifier 结果。仅保存最终文字回答，无法重现工具失败或检查 mask 是否偏移。对于会写文件、下单或发消息的工具，训练环境还应提供幂等模拟、资源配额和撤销路径；这既降低风险，也使同一轨迹能再次执行。

保留评测应改变任务表面、初始状态和工具错误模式。例如代理若在训练中总遇到固定字段顺序，评测应置换顺序、返回延迟或引入可恢复异常。报告要区分成功率、平均工具次数、总成本、超时与安全违规；一个依靠十倍调用次数换来的百分点提升，是否有价值取决于目标约束。这样定义环境和证据，才谈得上策略在新的交互状态上泛化。

离线轨迹也有边界：它只覆盖旧行为访问过的状态，无法可靠估计策略在新工具分支上的后果。离线数据可用于初始化价值模型、行为克隆或诊断，但当策略开始改变调用顺序时，通常仍需受控在线 rollout 取得新数据。为减少危险探索，可先在模拟器训练，再以只读权限、额度和人工复核逐级开放；这一过程改变的是可执行范围，不应被包装成算法已经解决现实世界安全问题。

若任务允许并行工具调用，归因还需区分并发分支与共享资源：一个超时可能来自调度而非某次 action。轨迹记录应保留因果顺序和请求标识，评测也要重放竞争条件，才能避免策略仅适应单线程模拟器。

最后，奖励权重是任务定义的一部分，应随环境版本保存。训练后再调评分公式来展示收益，会破坏不同策略之间的可比性；对关键约束应单列通过率，而非用一个平均回报掩盖严重失败。

## 常见误区

有函数调用不表示 Agentic RL：规则工作流、监督微调代理都可能从不做 RL。反过来，单轮 RLHF 也并不因使用 LLM 就自动成为长程代理学习。高分还可能是奖励投机、固定测试泄漏或模拟器漏洞；因此训练、调参与报告的评测环境必须分离。过细的过程奖励也会把一个可泛化目标替换为人工脚本。应报告终局成功、成本、失败类别和保留环境结果，而不只给一个加权总分。
