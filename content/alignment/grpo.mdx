# GRPO：用组内相对回报替代价值基线

import {GrpoLab} from '@site/src/components/AlgorithmLab';

## 直觉

GRPO（Group Relative Policy Optimization）由 DeepSeekMath 提出，是 PPO 的变体。对同一提示一次采样一组回答，用这组回答的相对奖励构造优势，避免像 PPO 那样另训练一个与策略同规模的 critic/价值模型。它常用于可判对错的推理任务，但算法本身不限定奖励必须来自规则或人类。

## 前置知识与简化公式

给提示 `q` 采样 `G` 个输出 `o_i`，得到回报 `r_i`。组内归一化优势常可简写为：

```
A_i = (r_i - mean(r_1...r_G)) / (std(r_1...r_G) + δ)
```

然后像 PPO 一样用新旧策略 token 概率比与裁剪项更新，并常加入相对 `πref` 的 KL 项。论文中的 token 级目标、长度归一化和 KL 估计有具体定义；上式仅说明关键直觉：成功样本相对同组更好才获正优势，不需单独 critic 给出全局基线。

## 流程

1. 从当前/旧策略为同一题生成 `G` 条回答。
2. 由奖励函数为每条打分，例如最终答案验证器。
3. 在该组内计算相对优势；同组全错或全同分时，学习信号可能很弱。
4. 用裁剪策略目标更新，并以参考策略或 KL 约束避免过快漂移。

## 小例子

一道方程题采样四条答案，验证器回报为 `[1,0,1,0]`。两个正确解高于组均值，获得正优势；错误解为负。若四条都正确，组内归一化并不意味着“继续把全部推高”的强信号，设计上强调同题候选之间的相对区分。

## 常见误区

GRPO 并非“完全没有 reference model”。其常用原始目标含对参考策略的 KL 正则，且还会有旧策略作为概率比的分母；它省掉的是独立 critic，而不是所有参照。也不要把组相对奖励当作天然可靠：组大小、奖励噪声、全零回报和采样多样性都会显著影响训练。
