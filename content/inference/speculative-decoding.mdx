# 投机解码：先猜一段，再由目标模型裁决

import {SpeculativeLab} from '@site/src/components/AlgorithmLab';

## 直觉

大模型逐 token 生成时，每多一个 token 都要做一次昂贵前向计算。投机解码把「便宜模型先猜、昂贵模型复核」拆开：草稿模型一次提出 `γ` 个候选，目标模型在一次并行前向中给出这些位置的概率；连续猜对的前缀直接提交。速度来自减少目标模型的串行轮数，不是跳过目标模型，也不应改变采样分布。

## 前置

设当前上下文为 `s`，目标分布为 `p_i(·)=p(·|s,y_1,…,y_{i-1})`，草稿分布为 `q_i(·)`；标准算法在同一 token 空间比较两者。接受率中的 `q_i` 必须是实际生成草稿的分布，`p_i` 必须是希望保留的目标采样分布（包括各自使用的温度、top-p 等变换），二者不必采用相同的采样参数。先按 `q_1,…,q_γ` 依次采样草稿 `y_1,…,y_γ`，再让目标模型并行算出各个 `p_i`。这里的 `p_i` 条件中含草稿前缀，是验证该路径所需的条件概率。

## 机制：精确的随机采样

第 `i` 个草稿 token 以概率 `a_i=min(1,p_i(y_i)/q_i(y_i))` 接受；可用均匀随机数决定。若第一次拒绝发生在 `i`，不要直接从 `p_i` 重抽，而要从**残差分布**采样：`r_i(x)=[p_i(x)-q_i(x)]_+ / Σ_v[p_i(v)-q_i(v)]_+`。若 `γ` 个草稿全被接受，再从目标的下一位置 `p_{γ+1}` 采一个 token。这个「接受 + 正残差」配对正是输出仍服从目标模型分布的原因；只接受、不做正确残差修正会引入偏差。

## 例子

草稿在某位置给 `A` 的概率为 0.40，目标给 0.30，则 `A` 的接受率是 0.75。抽中 `A` 后并非必然失败；只有随机数大于 0.75 才拒绝。拒绝时，剩余概率质量只从目标比草稿更看好的 token 中重分配，例如 `B` 若 `p(B)=0.50,q(B)=0.20`，会在残差中得到权重 0.30。它不是「改选目标最可能 token」的规则。

## 误区

常见的 greedy 玩具演示是：草稿每步取 `argmax q`，目标若同样取 `argmax p` 就接受，第一次不同便输出目标 argmax。这能说明前缀复用，也能复现目标的**贪心路径**；但没有 `p/q` 的随机接受和残差采样，不能拿来解释「采样分布无损」。真实加速还取决于接受长度、草稿成本、批量大小和 KV cache；草稿越长不必然越快。
